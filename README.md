# Pixelglow — рабочая версия (devnet)

Живое ончейн-поле пикселей на Solana по ТЗ (`../pixelglow_TZ.md`). Дизайн — `pixelglow_violet`.

## Как это устроено (вариант B из ТЗ, §3.1)

```
браузер ──(1 раз)── кошелёк подписывает сообщение: «разрешаю сессионному ключу X ставить пиксели до T»
   │
   │ клик → транзакция: memo "pg1:x,y,color", подписана сессионным ключом, fee payer = релеер проекта
   ▼
сервер (Node) ── проверяет строгий шаблон + холдинг $GLOW + лимит → подписывает как fee payer → отправляет в Solana
   │            ждёт подтверждения (WebSocket-подписка) → пиксель на холсте у всех (WebSocket /live)
   │
   ├─ индексер: кто владеет каждым пикселем, TWA живых пикселей по кошелькам за эпоху
   ├─ выплаты: каждые EPOCH_SEC — новые SOL в пул-кошельке (+перенос) → 80% холдерам по TWA, 20% в казну
   └─ read-only API: /api/wallet/<адрес> — живые пиксели, доля, ожидаемая выплата, история
```

- **Каждый пиксель = отдельная транзакция Solana** (memo-инструкция, видна в explorer).
- **Без попапов:** кошелёк подписывает одно сообщение (без SOL, без транзакции). Дальше клики подписывает сессионный ключ из браузера (хранится в IndexedDB, неэкспортируемый).
- **Бесплатно для игрока:** сетевую комиссию платит релеер проекта (10 000 лампортов за пиксель — в транзакции две подписи — ≈ 10 SOL на 1 млн пикселей). Дневной лимит — `RELAYER_DAILY_TX_CAP`.
- **Релеер нельзя «подоить»:** он подписывает только транзакцию ровно из [релеер, сессия, memo-программа] с одной memo-инструкцией. Тест на попытку вывода SOL — в `test/offline.test.js`.
- **Выплаты push-моделью:** SOL сам уходит на кошельки, пачками по 18 переводов. Пыль (< 0.0005 SOL) копится до следующей эпохи. Если никто не держал пиксели, пул переносится. Резерв на газ — 0.05 SOL.

## Запуск

Нужен Node 22+.

```bash
npm install
npm run setup                       # ключи релеера/пула/mint authority + тестовый $GLOW на devnet
npm run mint -- <адрес кошелька>    # выдать себе 1 000 000 тестовых $GLOW
npm run dev                         # сборка клиента + сервер на http://localhost:8787
```

Кошелёк (Phantom / Solflare / Backpack) переключи на **devnet**. Для `npm run setup` нужен devnet SOL на адресе mint authority: публичный кран часто отвечает 429, тогда пополни через https://faucet.solana.com.

Прочие команды:

| команда | что делает |
| --- | --- |
| `npm run fees -- 0.2` | имитирует комиссии создателя: отправляет 0.2 SOL в пул-кошелёк |
| `npm run e2e -- http://localhost:8787` | два бота-игрока: сессия, клики, перекраска, проверка холдинга, ожидание выплаты |
| `MIN_HOLD=0 npm test` | офлайн-тесты: TWA, подписи сессий, защита релеера |
| `EPOCH_SEC=60 npm start` | короткая эпоха для демонстрации выплат |

## Переход на mainnet

**Тест на mainnet до выпуска $GLOW:** `GLOW_MINT=SOL` и `MIN_HOLD=0.01` — доступ к рисованию и выплатам даёт сам SOL на кошельке. Настоящий токен потом подставляется одной переменной `GLOW_MINT=<mint>` (и `MIN_HOLD` в штуках токена). Кошельки релеера и пула на mainnet создаёт владелец проекта и сам вставляет их ключи в Render — пошагово в `MAINNET.md`; шаблон переменных — `mainnet.env`. Газ за выплаты платит релеер, поэтому в пул-кошельке остаются только комиссии; держи в нём ~0.002 SOL, чтобы счёт существовал. `RELAYER_DAILY_TX_CAP` ограничивает расход релеера в сутки.

1. `CLUSTER=mainnet-beta`, `RPC_URL` / `RPC_WS_URL` — платный RPC с WebSocket (Helius / Triton). Публичный RPC не выдержит нагрузку и режет по 429.
2. `GLOW_MINT=<настоящий mint $GLOW>`.
3. Свои ключи: положить `keys/relayer.json` и `keys/pool.json` (формат solana-keygen), пополнить релеер SOL.
4. Получатель creator fee на pump.fun → адрес пул-кошелька (`pool` из лога сервера). Опционально `TREASURY_ADDRESS`.
5. Хостинг: один процесс Node за HTTPS-прокси (nginx / Caddy), WebSocket на `/live`. Папки `keys/` и `data/` — на постоянный диск, с бэкапом.
6. Юрист (ТЗ §5) — до запуска.

## Что важно знать

- **Ключи** в `keys/` — это настоящие приватные ключи. Сейчас папка лежит в OneDrive. Для devnet это нормально, для mainnet ключи должны жить только на сервере.
- **Скорость:** на публичном devnet RPC подтверждение занимает ~0.8 с. 150 мс из ТЗ — это финальность Alpenglow в mainnet плюс быстрый RPC; код ждёт `confirmed` через WebSocket и ускорится сам.
- **Состояние холста** считает сервер (вариант B), но его можно пересобрать из цепочки: все клики — memo-транзакции с fee payer = релеер. Кроме того, сервер пишет `data/claims.jsonl` (подпись, слот, кошелёк, пиксель).
- **Порядок спорных кликов** (двое в один пиксель почти одновременно) определяется порядком подтверждения, который видит сервер. Для строгой честности можно сортировать по слоту — следующий шаг.
- Хранение — JSON-файл с атомарной записью раз в 10 с. Для большого онлайна стоит перейти на SQLite / Postgres.

## Хостинг: сайт на Vercel, сервер на Railway

Vercel — бессерверный хостинг: там нельзя держать WebSocket, фоновый цикл выплат и файлы на диске. Поэтому статический сайт живёт на Vercel, а сервер — на Railway (постоянный процесс).

**1. Railway (сервер)**
1. railway.com → New Project → Deploy from GitHub repo → этот репозиторий.
2. Variables → Raw Editor → вставить содержимое `railway.env` (создаётся командой `npm run railway-env -- https://<проект>.vercel.app`). Там приватные ключи: вставлять только в Railway.
3. Settings → Volumes → Add Volume, mount path `/data` (иначе холст и выплаты обнулятся при каждом деплое).
4. Settings → Networking → Generate Domain. Получится адрес вида `https://pixelglow-production.up.railway.app`, проверка: `/health` отвечает `ok`.

**2. Vercel (сайт)**
1. vercel.com → Add New → Project → этот репозиторий. Настройки сборки берутся из `vercel.json`.
2. Environment Variables: `PIXELGLOW_API` = адрес Railway из шага 1.4 (без `/` в конце).
3. Deploy. Если домен Vercel поменялся, обнови `ALLOWED_ORIGINS` на Railway.

**Важно:** пул-кошелёк один. Не держи локальный сервер и Railway запущенными одновременно, иначе оба будут платить из одного пула.
